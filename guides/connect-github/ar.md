## اربط حساب GitHub

من «شغّل بوتك» اختر **ريبو GitHub** وثبّت تطبيق Serverk على حسابك أو منظمتك، واختر الريبوهات التي نصل إليها. ثم اختر الريبو والفرع، ونتولى نحن الباقي.

الريبو الخاص مدعوم دون أن تعطينا أي توكن: يمنحنا التطبيق صلاحية قراءة مؤقتة وقت النشر فقط، ولا يراها بوتك أبدًا.

أما الريبو العام فلا يحتاج التطبيق: افتح `https://serverk.gg/bots/create?repo=owner/name` بريبو بوتك مكان `owner/name` وانشره مباشرة. يبدأ البوت حينها والنشر مع كل push موقوف، ويتفعّل حين تربط GitHub من قسم Git وتختار الريبو نفسه.

## كل push ينشر بوتك

عند تفعيل **انشر مع كل push** من قسم Git في إعدادات بوتك، ينشر كل push على الفرع المربوط بوتك من جديد تلقائيًا. ويرتبط كل نشر بـ commit واحد بالضبط، فتعرف دائمًا أي كود شغّال.

ونعرض حالة النشر على الـ commit نفسه في GitHub باسم `serverk/deploy`: جاري النشر، أو نجح، أو فشل.

## انشر بنفسك

اضغط **انشر من جديد** في صفحة بوتك، وننشر آخر commit على الفرع. وللنشر من أي مكان آخر، مثل GitHub Actions، انسخ **رابط النشر** من قسم Git: أي طلب `POST` إليه ينشر بوتك.

> [!warning] رابط النشر سري مثل كلمة المرور. لا تشاركه، وإذا انكشف فغيّره من قسم Git.

## ما الذي يتغيّر وقت النشر؟

يعيد النشر كل ملف موجود في الريبو إلى حالته في الـ commit، فيضيع أي تغيير على هذه الملفات، سواء أجريته من تبويب **الملفات** أو كتبه بوتك أثناء تشغيله. أما الملفات التي لم تكن في الريبو أصلًا، مثل `.venv` وملفات البيانات التي ينشئها بوتك، فتبقى كما هي. لذلك أبقِ ملفات البيانات مثل `data.json` و `bot.sqlite` خارج الريبو بإضافتها إلى `.gitignore`.
